# Bootstrap, agent installation and update

Bootstrap orchestrates agent installation, skills/MCP installation, configuration and diagnosis. Plans and skipped-phase reports are safe local paths; full provisioning/update is a separate clean-platform acceptance operation.

## Sub-features

- `bootstrap-plan`: phase ordering, selectors, interactive forwarding and text/JSON dry-run plans without execution.
- `bootstrap-report`: actual all-skipped/partial/success/failure outcomes, stdout/stderr separation and durable phase facts.
- `bootstrap-live`: real agent/skills/configure/doctor phases in clean isolation, including public console/module entry points and selective skips.
- `agents-picker`: selected/all agent binaries, checkbox cancellation/empty selection and installation failures.
- `stack-update`: explicit update of installed components in a previously provisioned acceptance HOME, followed by non-updating diagnosis.

## How to get to it (user POV)

- `agentic-bootstrap` or `uv run --frozen python -m agentic_env.bootstrap`.
- Bootstrap flags: `--skip-install-agents`, `--skip-install-skills`, `--skip-configure`, `--skip-doctor`; `--configure-no-skills`; repeat/comma `--server`, `--agent`, `--skill-agent`; `--skill-profile` (default `default`); `--interactive`, `--dry-run`, `--summary-format text|json`, `--verbose`, `--help`.
- `agentic-install-agents` or `uv run --frozen python -m agentic_env.install_agents`: terminal picker by default; `--all`, `--yes`, `--verbose`, `--verify-remote-contract`, `--help`. `--yes` alone without `--all` is a no-selection operation, not full installation.
- `agentic-update-stack` or `uv run --frozen python -m agentic_env.update_agentic_stack`: `--verbose`, `--verify-remote-contract`, `--help`. There is **no** updater dry-run, target selector, rollback or confirmation switch.
- Full provisioning/update uses existing `clean-acceptance.sh` and the [clean-platform runbook](../../../../README.md#clean-platform-acceptance); it does not belong to `drive bootstrap`.

## Driving it with the verifier CLI

Preconditions: [baseline](README.md#baseline-preconditions). No full stack is required for plan/all-skipped paths. Run each affected mode in both module/console and text/JSON variants; a dry-run is not actual provisioning proof.

- **Plans (`bootstrap-plan`)**: `python3 "$V" drive bootstrap --entry module --mode plan --format json`, then inspect. Require exit 0, one JSON document on the app's stdout, `dry_run: true`, four ordered phases (`install-agents`, `install-skills`, `configure`, `doctor`), actual requested argv, and every `executed: false`. Progress belongs to stderr; HOME/skills hashes remain unchanged. Wrapper stdout additionally prints its `Evidence:` footer: parse the retained app `stdout.txt`, not the wrapper's combined terminal output.
- **Text plan**: `python3 "$V" drive bootstrap --entry console --mode plan --format text`. Require readable planned commands, no phase execution and unchanged persistent state. Complete the opposite entry/format combinations when affected.
- **Actual empty workflow (`bootstrap-report`)**: `python3 "$V" drive bootstrap --entry module --mode skip --format json`. It executes the app with all four skip flags, not a dry-run. Require exit 0, `status: "ok"`, `dry_run: false`, all phases requested/executed false with concrete skip reasons, and no persistent writes. Repeat `--entry console --mode skip --format text` and remaining affected combinations.
- **Help**: `python3 "$V" drive help bootstrap --entry console`, `python3 "$V" drive help install-agents --entry module`, and `python3 "$V" drive help update --entry console`. These exercise help only, not provisioning/updating. Repeat other entry styles when changed.
- **Regression supplement**: `python3 "$V" drive tests --suite bootstrap` covers selectors, failure aggregation and reports; mocked child phases do not prove installed binaries, native installation or clean-host behavior.

For every remaining live journey, first obtain **explicit authority** for network downloads, binary installation/update and the selected isolated environment. The existing clean-acceptance wrapper rejects root, real HOME and nonempty fresh HOME, clears inherited credentials/configuration, and redirects writes to its acceptance HOME. Do not substitute ordinary host commands or claim this sandbox is a fresh machine.

Use the linked existing container or native fresh-HOME runbook. For Compose, add `--project-name` using the exact checkout profile reported by verifier doctor; record/check the project, run-created container IDs and source mount before use. Same-checkout runs must be serial, never attach to an existing/shared install, and never use fixed shared container names. Container evidence is Debian/Arch userland and its actual architecture, not native distro boot or native macOS/Windows proof. No trust/credentials/provider login is needed or authorized by this skill.

- **Clean provisioning (`bootstrap-live`)**: in the newly owned acceptance environment run `sh ./clean-acceptance.sh`. Require the real bootstrap phases, installed binaries at their reviewed version floors, configured files/hooks, native skills installation and the runner's final doctor/default-profile content checks. Capture command/stdout/stderr/exits and OS/architecture externally before removing the instance. `uv tool install --force .` installs the management package; it is separate from source-only `uv run --frozen` development. Setup steps supplied by a container (prerequisite tools, user, mounts) remain unverified on a real target that lacks them.
- **Update then checks (`stack-update`)**: retain the **same provisioned acceptance HOME**, then run `sh ./clean-acceptance.sh --update`, followed by `SKIP_INSTALL=1 sh ./clean-acceptance.sh`. Require updater exit 0 and post-update checks pass. Inspect component versions/files before/after; installed-component updates and missing-component skips must match actual state. Checks-only never installs or updates components, but may populate caches. A newly recreated container cannot supply checks-only evidence for a discarded installation. The updater does not upgrade the management package or refresh standalone copied skills.
- **Selector/partial/report variants (`bootstrap-plan`, `bootstrap-report`)**: only inside that authorized isolated shell, run `uv run --frozen python -m agentic_env.bootstrap --dry-run --summary-format json --agent omp --server codebase-memory-mcp --skill-agent claude,codex --configure-no-skills`; inspect forwarded argv and no writes. Repeat selectors as separate flags and comma values, each enabled agent/server/skill target and nonempty profile when affected. `agentic-bootstrap --skip-install-agents --skip-install-skills --skip-configure --summary-format json` actually runs doctor only: require `partial`/exit 0 if it succeeds, or `failed`/exit 1 with errors if it does not. Cover each individual skip flag and mixed skips that affect the change, without silently treating skipped phases as executed.
- **Invalid/failure (`bootstrap-report`)**: `agentic-bootstrap --skill-profile '' --dry-run --summary-format json` and `agentic-bootstrap --agent not-an-agent --dry-run --summary-format json` must exit 1 without phase execution (a valid JSON report is not promised for rejected arguments). Invalid `--summary-format yaml` exits 2. Returned/raised phase failure must yield overall `failed`/exit 1 with its error/duration while subsequent phases are still attempted; a real controllable dependency/network failure is required for live proof, otherwise name the blocked precondition. Never replace the child with a fake success/failure to claim live coverage.
- **Interactive (`agents-picker`, `bootstrap-live`)**: `agentic-install-agents` waits at `Select agent CLIs to install`; select Hermes, OMP, Codex or Claude, or all via `agentic-install-agents --all --yes`. Require actual chosen binaries/versions and unselected skip messages. Clearing all choices exits 0 without installation; Ctrl-C at the picker exits 130. `agentic-bootstrap --interactive` must reach both install phases' real pickers; cancellation stops the workflow and may produce no JSON report. Use the [skills picker map](skills-install.md) for destination/MCP/confirmation branches. Do not send timed blind keystrokes.
- **Other options**: run `agentic-install-agents --verify-remote-contract` and `agentic-update-stack --verify-remote-contract` only in this isolation; require the named contract-success message and no installation/update. Repeat affected native operations with `--verbose`. For updater failure, retain the actual failed boundary and post-run state; absence of a selected installed component is a skip, not a successful update of it.

## Gotchas

- No local helper command performs full provisioning/update. If authority, prerequisites or a clean isolated target are absent, those paths are **blocked**, explicitly named; plan/all-skipped output is not a substitute. User-requested one-feature proof can be complete without claiming every mapped feature passed.
- Default bootstrap is noninteractive all-agent/all-MCP installation with an explicit skill profile; interactive mode forwards empty install argv so users can choose. Skill profiles and checkout isolation profiles are unrelated.
- JSON reports describe phase requests/execution, not proof that side effects succeeded. Inspect version output and files. Argument errors/cancellation can omit JSON; do not force them into a fabricated report. All-skipped `ok` differs from partially skipped `partial`.
- Bootstrap/update have no rollback; interruption after an installer starts may leave effects. Pre-install cancellation/no-write and post-start interruption are different cases. Retain logs, inspect and clean only owned scratch instances.
- An updater confirmation/decline or empty-picker path is N/A: it has no picker/confirmation API. Auth/provider login and persistent TCP readiness are N/A for orchestrator acceptance; any external network/browser behavior must still be observed and reported. Kill only run-created container/process IDs, never names shared with other work; retain acceptance proof outside teardown targets.
