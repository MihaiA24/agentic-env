# Stack diagnosis and skill drift

Read the installed-stack contract or compare complete skill packages with reviewed sources, installed copies and upstreams. Diagnosis reports findings; it does not repair files or install/update components.

## Sub-features

- `stack-diagnose`: OMP mandatory failures versus secondary warnings, current version floors, hooks/settings/MCP/descriptor findings and corrective commands.
- `drift-source`: offline reviewed-source comparisons scoped by pack, text/JSON, and incomplete-versus-drift exit semantics.
- `drift-installed`: canonical managed-store contents/provenance, optional absent skills versus explicitly required profiles and unmanaged entries.
- `drift-upstream`: pinned/latest and local/upstream whole-package comparisons, online diffs and offline/cache limits.
- `drift-review`: explicit reviewed-baseline recording, preservation of unselected/unresolved packs and write failures; separate authorization from read-only verification.

## How to get to it (user POV)

- `agentic-stack-doctor` or `uv run --frozen python -m agentic_env.stack_doctor`; only `--help` is exposed. This is not the verifier's freshness/ownership `doctor`.
- `agentic-skill-drift` or `uv run --frozen python -m agentic_env.skill_drift`: repeatable `--pack` **or** `--skill-profile` (mutually exclusive), `--skill-config`, `--offline`, `--no-upstream`, `--no-installed`, `--diff`, `--json`, `--update-baseline`, `--help`.
- `--pack` is repeated, not comma-separated. There is no drift `--skills-dir`: installed checks always use canonical `~/.agents/skills`, never custom/copier destinations.

## Driving it with the verifier CLI

Preconditions: [baseline](README.md#baseline-preconditions). Offline source success needs locally packaged source packs; remote packs may need cached source trees. This empty sandbox is not a fully installed stack.

- **Read-only diagnosis (`stack-diagnose`)**: `python3 "$V" drive stack-doctor --entry module`, then inspect. Retain actual exits/findings; an unprovisioned HOME is expected to fail mandatory configuration/descriptor checks. Managed configuration and skill hashes must remain unchanged. External version probes can create disposable runtime files/executable links (observed for Codex); record those effects rather than claiming all HOME bytes stayed unchanged. Existing PATH tools do not prove clean installation. Repeat `--entry console` when affected.
- **Product success/severity (`stack-diagnose`)**: after separately authorized real clean provisioning, run `agentic-stack-doctor` in that acceptance environment. Require exit 0/`stack OK` when mandatory checks pass; secondary Hermes/Claude/Codex/agentmemory findings warn with `TODO secondary` rather than forcing exit 1. Missing/below-floor mandatory tools, bad OMP wiring/settings/hooks/descriptors and forbidden interception prose must produce exit 1 and specific correction guidance. Curated skill omission alone is not a doctor failure. Real faulty user-config/version fixtures are required when changing these branches; missing fixtures are blocked, not covered by the sandbox's unrelated missing-config failure.
- **Local source JSON (`drift-source`)**: `python3 "$V" drive drift --entry module --pack mattpocock --pack pstack --format json`. Require app stdout to be one JSON object with `skills`/`unmanaged`; selected source rows compare reviewed package fingerprints, and installed/upstream columns are skipped. Inspect afterward: no source/baseline/installed files changed. Parse retained `stdout.txt`, not wrapper stdout with its `Evidence:` footer.
- **Local source text**: `python3 "$V" drive drift --entry console --pack agentic-env --format text`; require table/findings for that pack and skipped non-comparable upstream. Repeat affected entry/style/pack variants; do not demand a particular pass if source bytes actually differ from the reviewed baseline.
- **Scope/error/incomplete (`drift-source`)**: `python3 "$V" drive drift --pack not-a-pack` must exit 1 with `Unknown pack(s)` and no writes. `python3 "$V" drive drift --pack ponytail --format json` in an uncached sandbox may exit 2/unknown, not 0 merely because offline was requested. Omit `--pack` to exercise the entire manifest: each requested unknown takes precedence over drift. Capture actual results, never interpret `skipped` as `unknown` or vice versa.
- **Help/regression supplements**: `python3 "$V" drive help stack-doctor --entry console`, `python3 "$V" drive help drift --entry module`, `python3 "$V" drive tests --suite doctor`, `python3 "$V" drive tests --suite drift`. Suites are supporting checks, not live installed/upstream proof.

The bounded helper always adds `--offline --no-upstream --no-installed`; it cannot prove the following canonical-install/upstream/baseline paths. With explicit authority, use the owned isolated environment from [bootstrap/update](bootstrap-update.md), never the daily host for mutations. Run exact public commands there:

- **Installed selection (`drift-installed`)**: `agentic-skill-drift --pack mattpocock --offline --no-upstream --json`, after real native managed installation. Require matching content as `ok`, intentionally absent optional skills as `not installed` rather than drift, and no repair. `agentic-skill-drift --skill-profile default --offline --no-upstream --json` requires that whole profile: absent skills become `missing`. Preserve the actual installed selection; do not install a whole profile merely to clear findings.
- **Modified/foreign/unmanaged (`drift-installed`)**: after an ordinary user edit of an installed sandbox package, rerun the same command; require `modified` and a recovery command limited to that skill. Remote provenance uses the native skills lock; matching vendored bytes take precedence over stale lock origins. A real alternate remote installation is required for `foreign:<source>` proof, not a fabricated lock. Unknown local packages appear in unmanaged findings; `--no-installed` suppresses both installed and unmanaged scans. Compare read-only contents/hashes before/after diagnosis.
- **Online comparisons (`drift-upstream`)**: `agentic-skill-drift --pack mattpocock --pack pstack --no-installed --diff --json`. Require resolved pinned/latest refs and whole-package upstream/local diffs (including non-Markdown assets); a local adaptation can make `Local/upstream: different` without itself counting as drift. A null diff means not computed; an empty diff string means no difference. Repeat `--no-upstream` and `--offline` separately when changed: offline cached sources cannot establish today's upstream ref. Cold-cache, network/Git/download failure and source drift need their real disposable prerequisites; missing prerequisites are blocked. Do not execute downloaded skills.
- **Option validation (`drift-source`)**: `agentic-skill-drift --pack pstack --skill-profile default` exits 2; so do `agentic-skill-drift --offline --diff`, `agentic-skill-drift --no-upstream --diff`, and `agentic-skill-drift --update-baseline --diff`. Unknown profile exits 1. A reviewed custom-manifest fixture passed via `--skill-config` must remain in emitted per-skill recovery commands; missing/invalid manifests exit 1 without a fabricated findings document.
- **Reviewed baseline only (`drift-review`)**: requires **separate explicit write authority**, a reviewed source change and a disposable writable checkout, not the read-only container source mount or ordinary helper. From that checkout's root run `uv run --frozen python -m agentic_env.skill_drift --pack pstack --no-installed --no-upstream --update-baseline`. Require only selected fully resolved pack entries updated, unselected entries preserved; exit 0 if all selected fingerprints were recorded, 2 if any were unresolved, 1 on unreadable/unwritable baseline. Unresolved packs retain their previous whole entry; if none resolve, the file is not rewritten. Retain before/after baseline hashes/diff and the review decision. This mutation intentionally changes source and invalidates the old verifier fingerprint; relaunch before subsequent proof.

## Gotchas

- Drift exits: 0 means no drift in requested completed checks; 1 means drift or invalid manifest/pack/profile; 2 means incomplete requested checks or CLI usage error. An unknown result takes priority over known drift. An explicitly disabled/not-applicable comparison is `skipped`, not a completed check.
- Source/install/upstream fingerprints cover complete packages, not just frontmatter. Local/upstream difference is informational, distinct from pinned/latest drift. Remote caches can change even on read-only checks; track permitted cache writes separately from forbidden source/install/baseline changes.
- Read-only verification never runs `--update-baseline` to silence a finding, never runs an emitted reinstall/fix command automatically, and never upgrades a live stack. Doctor/drift cannot verify standalone copied directories or runtime discovery.
- Cancellation/decline and empty-picker paths are N/A: neither command offers an interactive picker/confirmation. Omitted drift scope means all manifest packs, not an empty selection. Interruption/network failure is incomplete evidence, not app cancellation success. TCP/browser/provider auth is N/A to these CLI comparisons; permitted upstream requests still require actual network observations when claiming no network occurred.
- Wrapper doctor before/after and unchanged source identity bind the proof to this checkout. Retain all findings (including expected errors), observe state after the public path, then clean only owned scratch state while keeping evidence.
