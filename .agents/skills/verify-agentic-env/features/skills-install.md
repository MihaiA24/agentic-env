# Skills installation, destinations and pickers

Choose skills, install complete packages through the native skills CLI into a custom folder or managed agent roots, and optionally install MCP tools. Guided selection is distinct from successful native installation.

## Sub-features

- `install-custom`: an exact custom skills folder receives selected complete packages, without managed agent roots, MCP installation or global provenance.
- `install-managed`: selected canonical/agent destinations, local or remote packs, optional MCP tooling and persisted discovery layout.
- `install-select`: profile/pack/name/custom-manifest selectors, repeated/comma forms and all-skills/all-MCP modes.
- `install-picker`: skills, destination, custom-path/agent and MCP prompts; descriptions, replay summary, confirmation, cancellation and intentionally empty choices.
- `install-reject`: unknown/partially invalid/empty selections, incompatible options, collisions and native dependency/network/install failure.

## How to get to it (user POV)

- `agentic-install-skills-mcps` or `uv run --frozen python -m agentic_env.install_skills_mcps`; no selection flags on a TTY opens guided pickers. `--yes` uses flags without prompts; no TTY means no picker.
- `--skills-dir PATH` selects custom directory mode. Otherwise `--skill-agent` selects `hermes`, `claude`, `codex` targets (repeat/comma; default configured targets). OMP is discovered through Claude's skill root, not `--skill-agent omp`.
- Selection flags: `--skill-profile`, `--skill-pack`, `--skill`, `--skill-config`, `--all-skills`. MCP flags: `--mcp codebase-memory-mcp`, `--mcp agentmemory`, `--all-mcps`. Other public routes: `--yes`, `--verbose`, `--verify-remote-contract`, `--help`.
- `agentic-bootstrap --interactive` reaches these pickers too; [bootstrap/update](bootstrap-update.md) also covers the separate agent-binary picker.

## Driving it with the verifier CLI

Preconditions: [baseline](README.md#baseline-preconditions). Native installation needs already available npm/Git and permitted downloads even for vendored packages. Never install missing prerequisites or change the user's host stack for this proof. Each independent success starts with a fresh owned destination.

- **Live native custom success (`install-custom`)**: `python3 "$V" drive install-skills --entry module --pack mattpocock --skill writing-for-agents`, then `python3 "$V" drive inspect`. Require exit 0, complete source-matching package files, and no files under sandbox agent roots or global skills lock/provenance. This path calls the real native runner, not a staged test replacement. Repeat fresh with `--entry console` when affected. Local pack alternatives are `--pack pstack --skill how` and `--pack agentic-env --skill apache-spark-static`; a pack default is not a profile.
- **Custom collision/error (`install-reject`)**: rerun the same successful native command; require nonzero refusal and unchanged package hashes. Independently run `python3 "$V" drive install-skills --skill ''` and `python3 "$V" drive install-skills --skill writing-for-agents,not-a-skill`; require exit 1/no partial write. If npm/network fails on a valid selection, retain that failure and report native success blocked, not passed via the copier.
- **Wrapper plan is not proof**: `python3 "$V" drive install-skills --pack mattpocock --skill writing-for-agents --dry-run` must print `executed: false`/`evidence: false`. It tests no native installation and makes no npm/network call.
- **Help entry points**: `python3 "$V" drive help install-skills --entry module` and `python3 "$V" drive help install-skills --entry console` must list actual public options and exit 0. A help run does not exercise those options.
- **Existing PTY regression supplement (`install-picker`)**: `python3 "$V" drive tests --suite pickers`. It waits on actual prompt strings, not sleeps. Its installation boundary is mocked; even its custom-directory file-copy test is **not native skills CLI proof**.

The following **live** terminal journeys require explicit authority and an owned isolated acceptance container/fresh HOME, reached via the [existing acceptance runbook](../../../../README.md#clean-platform-acceptance). This wrapper deliberately supplies no arbitrary-command/PTY passthrough. Use the checkout-derived, owned namespace and external transcript rules in [bootstrap/update](bootstrap-update.md); do not attach to an existing host or shared container. These exact app commands run **inside that isolated environment**, never on the daily host:

- **Guided custom (`install-picker`)**: run `uv run --frozen python -m agentic_env.install_skills_mcps --skill writing-for-agents`. At `Select skills to install`, confirm the prechecked skill; at `Install skills where?`, choose **Other / custom directory**; at `Skills directory (exact folder)`, first enter blank (require `Enter a skills directory`), then type `~/verification custom/skills` (the app expands `~` to the isolated HOME). Require no agent/MCP picker, a selection/replay command, then confirm `Install this selection`. Exit 0 plus source-matching package hashes in that exact folder proves native success. Replay the printed command into a new empty destination to prove replay equivalence.
- **Guided managed (`install-picker`, `install-managed`)**: run the same command in a fresh acceptance HOME; select **Supported harnesses**, then targets at `Install skills for which agents?`, then choices at `Select MCP tooling`, then confirm. Exercise Space toggle, `a` all, `i` invert, pack-wide rows versus individual rows, highlighted descriptions, and replay summary when those paths change. Require only chosen destinations/MCP tools and observed binaries/files, not just a successful prompt transcript.
- **Cancel/decline/empty (`install-picker`)**: independently Ctrl-C at skills, destination, exact-folder and agent/MCP selection prompts (require exit 130/no install). Decline `Install this selection` (exit 0, `nothing installed`, no writes). Clear all skills and MCPs (exit 0, all three skip messages, no agent prompt/no writes). Clear every agent with skills selected, then clear MCPs (no skill install). Exercise Ctrl-C at confirmation separately; record its actual cancellation exit, not an assumed normalized report. Capture before/after HOME and destination hashes for every case.
- **Selectors (`install-select`)**: independently run `agentic-install-skills-mcps --skill-pack mattpocock --skill tdd,code-review --skill-agent claude,codex --yes` and the equivalent repeated flags `agentic-install-skills-mcps --skill-pack mattpocock --skill tdd --skill code-review --skill-agent claude --skill-agent codex --yes`. Require only selected packages/targets and matching complete contents. Also cover `--skill-profile default`, `--all-skills`, repeated/comma pack names, and each enabled target/MCP selection when affected; run full/native provisioning only under its separate authority.
- **Custom options (`install-select`, `install-reject`)**: `agentic-install-skills-mcps --skills-dir "$HOME/verification custom/skills" --skill-pack mattpocock --skill writing-for-agents --yes` on a fresh destination proves spaces/exact-folder semantics. Repeat separately with `--skill-profile default` or `--all-skills` when affected. Combine this command with `--skill-agent codex`, `--mcp agentmemory`, or `--all-mcps` one at a time: each must fail before writing. A custom `--skill-config` journey needs an actual reviewed manifest fixture; prove preserved selector/replay semantics, rostered invalid-name rejection and unrostered native delegation. Missing that manifest is blocked, not implicit coverage by the built-in manifest.
- **MCP/diagnostic routes**: in the same authorized isolation, `agentic-install-skills-mcps --mcp codebase-memory-mcp --yes`, `agentic-install-skills-mcps --mcp agentmemory --yes`, and `agentic-install-skills-mcps --all-mcps --yes` require actual selected binary/version results and unselected skips. Cover the interactive `Install codebase-memory-mcp with UI` yes/no choices when changed. `agentic-install-skills-mcps --verify-remote-contract` exits without installing; repeat affected operations with `--verbose` and capture expanded child output.

## Gotchas

- Capture terminal actions, real exits and a second read-only file/link/hash view. No fixed sleeps; wait for the named prompt. Missing live-PTY/native/fixture prerequisites are blocked branches, not N/A or passes borrowed from regression tests.
- Managed targets differ: default Claude/Hermes links use canonical `~/.agents/skills`; Claude-only can create copies without a canonical Codex store. Confirm the chosen layout and load a selected skill in the intended runtime separately. Do not grant Hermes trust for discovery proof.
- An empty guided selection is a successful no-op; explicit empty/partly invalid names fail before installation. Noninteractive `--yes` alone is not bootstrap's explicit `default` profile request.
- Custom directory mode makes standalone copies and refuses existing selected names, including dangling symlinks. It does not refresh via the updater. Partial filesystem failure can leave incomplete new packages; preserve them and retry fresh.
- Cancellation after downloads/install starts can leave effects; it is not equivalent to pre-confirmation cancellation. Auth/browser/TCP are N/A for choosing skills; any external installer that opens a browser or uses network must be reported/observed, not assumed absent because the pack is local.
