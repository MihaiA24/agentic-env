# Skills installation, destinations and pickers

Choose skills, install complete packages into a custom folder (Python copy, no skills CLI) or managed agent roots (native skills CLI), and optionally install MCP tools. Guided selection is distinct from successful installation.

## Sub-features

- `install-custom`: an exact custom skills folder receives selected complete packages, without managed agent roots, MCP installation or global provenance.
- `install-managed`: selected canonical/agent destinations, local or remote packs, optional MCP tooling, the agent rules file (opt-in here, passed by bootstrap) and persisted discovery layout.
- `install-select`: profile/pack/name/custom-manifest selectors, repeated/comma forms and all-skills/all-MCP modes.
- `install-picker`: skills, destination, custom-path/agent, MCP and agent-rules prompts; descriptions, replay summary, confirmation, cancellation and intentionally empty choices.
- `install-reject`: unknown/partially invalid/empty selections, incompatible options, collisions, the overwrite prompt, and dependency/network/install failure.
- `install-converge`: `--converge` lock-held refresh, new-host profile fallback, offer-once picker and its lock record, and dropped-skill removal or kept reports.

## How to get to it (user POV)

- `agentic-install-skills-mcps` or `uv run --frozen python -m agentic_env.install_skills_mcps`; no selection flags on a TTY opens guided pickers. `--yes` uses flags without prompts; no TTY means no picker.
- `--skills-dir PATH` selects custom directory mode. Otherwise `--skill-agent` selects `hermes`, `claude`, `codex` targets (repeat/comma; default configured targets). OMP is discovered through Claude's skill root, not `--skill-agent omp`.
- Selection flags: `--skill-profile`, `--skill-pack`, `--skill`, `--skill-config`, `--all-skills`. MCP flags: `--mcp codebase-memory-mcp`, `--mcp agentmemory`, `--all-mcps`. `--agent-rules` writes the optional rules file `~/.agents/AGENTS.md`. Other public routes: `--yes`, `--verbose`, `--verify-remote-contract`, `--help`.
- `--converge` is bootstrap's skills phase; it rejects `--skill-pack`, `--skill`, `--all-skills` and `--skills-dir`, and needs `--skill-profile` for a new host.
- `agentic-bootstrap --interactive` reaches these pickers too; [bootstrap/update](bootstrap-update.md) also covers the separate agent-binary picker.

## Driving it with the verifier CLI

Preconditions: [baseline](README.md#baseline-preconditions). Custom-directory installation of local packs needs no npm, Git or network; remote packs need network. Never install missing prerequisites or change the user's host stack for this proof. Each independent success starts with a fresh owned destination.

- **Live custom success (`install-custom`)**: `python3 "$V" drive install-skills --entry module --pack mattpocock --skill writing-for-agents`, then `python3 "$V" drive inspect`. Require exit 0, complete source-matching package files, and no files under sandbox agent roots or global skills lock/provenance. This path calls the real installer, not a staged test replacement. Repeat fresh with `--entry console` when affected. Local pack alternatives are `--pack pstack --skill how` and `--pack agentic-env --skill apache-spark-static`; a pack default is not a profile.
- **Custom collision/error (`install-reject`)**: rerun the same successful command (it passes `--yes`); require exit 1, the `rerun on a terminal without --yes` hint and unchanged package hashes. Independently run `python3 "$V" drive install-skills --skill ''` and `python3 "$V" drive install-skills --skill writing-for-agents,not-a-skill`; require exit 1/no partial write.
- **Wrapper plan is not proof**: `python3 "$V" drive install-skills --pack mattpocock --skill writing-for-agents --dry-run` must print `executed: false`/`evidence: false`. It tests no installation and copies nothing.
- **Help entry points**: `python3 "$V" drive help install-skills --entry module` and `python3 "$V" drive help install-skills --entry console` must list actual public options and exit 0. A help run does not exercise those options.
- **Existing PTY regression supplement (`install-picker`)**: `python3 "$V" drive tests --suite pickers`. It waits on actual prompt strings, not sleeps. Its installation boundary is mocked; it is **not installation proof**.

The following **live** terminal journeys require explicit authority and an owned isolated acceptance container/fresh HOME, reached via the [existing acceptance runbook](../../../../README.md#clean-platform-acceptance). This wrapper deliberately supplies no arbitrary-command/PTY passthrough. Use the checkout-derived, owned namespace and external transcript rules in [bootstrap/update](bootstrap-update.md); do not attach to an existing host or shared container. These exact app commands run **inside that isolated environment**, never on the daily host:

- **Guided custom (`install-picker`)**: run `uv run --frozen python -m agentic_env.install_skills_mcps --skill writing-for-agents`. At `Select skills to install`, confirm the prechecked skill; at `Install skills where?`, choose **Other / custom directory**; at `Skills directory (exact folder)`, first enter blank (require `Enter a skills directory`), then type `~/verification custom/skills` (the app expands `~` to the isolated HOME). Require no agent/MCP picker and no agent-rules question, a selection/replay command, then confirm `Install this selection`. Exit 0 plus source-matching package hashes in that exact folder proves native success. Replay the printed command into a new empty destination to prove replay equivalence.
- **Guided managed (`install-picker`, `install-managed`)**: run the same command in a fresh acceptance HOME; select **Supported harnesses**, then targets at `Install skills for which agents?`, then choices at `Select MCP tooling`, then yes or no at `Install the recommended agent rules to`, then confirm. Exercise Space toggle, `a` all, `i` invert, pack-wide rows versus individual rows, highlighted descriptions, and replay summary when those paths change. Require only chosen destinations/MCP tools and observed binaries/files, not just a successful prompt transcript. A yes to the rules question must show `Agent rules:` in the summary, `--agent-rules` in the replay command and `~/.agents/AGENTS.md` on disk; a no must leave that path untouched.
- **Cancel/decline/empty (`install-picker`)**: independently Ctrl-C at skills, destination, exact-folder, agent/MCP selection and agent-rules prompts (require exit 130/no install). Decline `Install this selection` (exit 0, `nothing installed`, no writes). Clear all skills and MCPs and answer no to the agent rules (exit 0, all four skip messages, no agent prompt/no writes). Clear every agent with skills selected, then clear MCPs (no skill install). Exercise Ctrl-C at confirmation separately; record its actual cancellation exit, not an assumed normalized report. Capture before/after HOME and destination hashes for every case.
- **Overwrite prompt (`install-reject`)**: install `--skill tdd` into a custom folder, edit its `SKILL.md`, then rerun on a terminal without `--yes`. Require `Overwrite 1 existing skill(s)`; answer no (exit 0, `existing skills kept`, unchanged hashes, no download), then rerun and answer yes (exit 0, source-matching package, no hidden `.tdd.*` staging folder, unrelated files intact).
- **Selectors (`install-select`)**: independently run `agentic-install-skills-mcps --skill-pack mattpocock --skill tdd,code-review --skill-agent claude,codex --yes` and the equivalent repeated flags `agentic-install-skills-mcps --skill-pack mattpocock --skill tdd --skill code-review --skill-agent claude --skill-agent codex --yes`. Require only selected packages/targets and matching complete contents. Also cover `--skill-profile default`, `--all-skills`, repeated/comma pack names, and each enabled target/MCP selection when affected; run full/native provisioning only under its separate authority.
- **Custom options (`install-select`, `install-reject`)**: `agentic-install-skills-mcps --skills-dir "$HOME/verification custom/skills" --skill-pack mattpocock --skill writing-for-agents --yes` on a fresh destination proves spaces/exact-folder semantics. Repeat separately with `--skill-profile default` or `--all-skills` when affected; those fetch the remote caveman/ponytail tarballs. Combine this command with `--skill-agent codex`, `--mcp agentmemory`, `--all-mcps`, or `--agent-rules` one at a time: each must fail before writing. A custom `--skill-config` journey needs an actual reviewed manifest fixture; prove preserved selector/replay semantics, rostered invalid-name rejection, and that a rosterless pack needs explicit `--skill` names in directory mode. Missing that manifest is blocked, not implicit coverage by the built-in manifest.
- **MCP/diagnostic routes**: in the same authorized isolation, `agentic-install-skills-mcps --mcp codebase-memory-mcp --yes`, `agentic-install-skills-mcps --mcp agentmemory --yes`, and `agentic-install-skills-mcps --all-mcps --yes` require actual selected binary/version results and unselected skips. Cover the interactive `Install codebase-memory-mcp with UI` yes/no choices when changed. `agentic-install-skills-mcps --verify-remote-contract` exits without installing; repeat affected operations with `--verbose` and capture expanded child output.
- **Agent rules (`install-managed`)**: in a fresh isolated HOME, `agentic-install-skills-mcps --agent-rules --yes` must print `agent rules: installed at` and leave `~/.agents/AGENTS.md` byte-identical to `agentic_env/rules/AGENTS.md`. A second run prints `agent rules: already current at` and writes nothing. With a different file already at that path, the run keeps the old bytes in `AGENTS.md.agentic-env.bak`, and the guided question adds `replaces your file`. Replacing an outdated managed file (first line `<!-- Installed by agentic-env`) leaves that backup unchanged. A `--yes` run without the flag prints `agent rules: skipped`. Needs no npm or network.
- **Converge (`install-converge`)**: in an isolated HOME with `XDG_STATE_HOME` unset, run `agentic-install-skills-mcps --converge --skill-profile default --skill-agent claude,codex`. Without a lock it installs the profile. On a terminal the offer picker records all shown names as `dismissed["agentic-env:offered:<name>"]: true` in `~/.agents/.skill-lock.json`. On repeat the app refreshes only lock-held roster skills and does not offer those names again. Ctrl-C records nothing; `--yes` or no TTY offers and records nothing. Repeat with `XDG_STATE_HOME` set and a truncated, unreadable, or unsupported lock. Require exit 1, the exact lock path in the diagnostic, and no update, install, pruning, or lock changes.
- **Dropped skills (`install-converge`)**: use the native CLI to install a retired fixture from the exact configured pack path into the canonical store with a Claude symlink. Run converge with that name in the custom manifest's `dropped` list. Verify the folder, link, and its lock record disappear while unrelated lock fields remain. Repeat with an edited package, a different local source with the same suffix, and an independent Claude copy. Require the corresponding files and records to remain and the app to report each reason.

## Gotchas

- Capture terminal actions, real exits and a second read-only file/link/hash view. No fixed sleeps; wait for the named prompt. Missing live-PTY/native/fixture prerequisites are blocked branches, not N/A or passes borrowed from regression tests.
- Managed targets differ: default Claude/Hermes links use canonical `~/.agents/skills`; Claude-only can create copies without a canonical Codex store. Confirm the chosen layout and load a selected skill in the intended runtime separately. Do not grant Hermes trust for discovery proof.
- An empty guided selection is a successful no-op; explicit empty/partly invalid names fail before installation. Noninteractive `--yes` alone is not bootstrap's explicit `default` profile request.
- Custom directory mode makes standalone copies. `--yes` or no TTY refuses existing selected names, including dangling symlinks; a terminal run asks before overwriting them. Bootstrap does not refresh them. Partial filesystem failure can leave incomplete new packages; preserve them and retry fresh.
- Cancellation after downloads/install starts can leave effects; it is not equivalent to pre-confirmation cancellation. Auth/browser/TCP are N/A for choosing skills; any external installer that opens a browser or uses network must be reported/observed, not assumed absent because the pack is local.
