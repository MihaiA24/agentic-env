## Local adaptations

- Native loading (`skill://`, `skill_view`) and delegation (`task`, `delegate_task`); independent work may fan out, small work stays inline. Authoring mechanics distinguish manual discovery from named dependency loading, and describe the catalog entry as a routing hint a harness may shorten (OMP 18.18 shows about 100–160 characters), so the distinguishing trigger goes first.
- `research` (2026-10-25): replaced mandatory background delegation with inline focused lookups and conditional delegation of substantial independent reading while other useful work continues. Replaced mandatory repository Markdown with a cited reply by default; save or update a note only when requested or needed as a reusable research record. Chat-only/read-only requests create no note. Primary-source evidence and full requested scope are retained; no skills were added or removed.
- `code-review` uses the local `scripts/review_snapshot.py`: explicit refs/scoped WIP, unchanged user staging, shared frozen context and before/after integrity checks. Intent can come from the user, not only commits. Hashes are not write restrictions; reviewers need restricted grants or tool-less input, and `scout` is read-only only by its checked tool grant.
- `code-review` ships a local `STANDARDS.md`: six shared review lenses condensed from Lauren Tan's pstack `principle-*` skills (`cursor/plugins` @ `c1c0a32`, [MIT, Lauren Tan](../pstack/LICENSE)), not Matt's work. The Standards axis applies it in every repo, below the repo's own standards and above the smell baseline.
- Tracker consumers use `docs/agents/issue-tracker.md` rather than the excluded setup skill; ask when configuration is missing.
- `wizard` is manual-only with metadata and body guards. Approve stages/destinations, never inspect secret files, and leave execution to the human. Hermes does not enforce the metadata flag.
- `wizard/template.sh` writes literal single-line dotenv values, not shell quote concatenation. Enter-to-keep reads hand-edited lines as dotenv readers do (surrounding whitespace, inline ` # comments`, a comment after a closing quote); upstream keeps those raw and empties `"a\nb"`. Forms readers disagree on (`a#b`, backticks, text after a closing quote, unclosed quotes) or that this quoting subset cannot represent losslessly fail before file mutation; use a consumer-specific serializer for them.
- `prototype`, `wayfinder`, `to-spec`, `to-tickets` and `wizard` gate publication separately. `wayfinder` research branches are created or pushed only on request, never PR'd; `to-tickets` names sub-issue attachment in the breakdown the user approves.
- `improve-codebase-architecture` surveys without refactoring or requiring a lone worker.
- The `CONTEXT.md` convention stays: upstream `d80fa0f` renamed `CONTEXT.md`, `CONTEXT-MAP.md` and `CONTEXT-FORMAT.md` to `GLOSSARY*`, but the user's repos use the old names. `domain-modeling` (with `CONTEXT-FORMAT.md`), `codebase-design`, `diagnosing-bugs`, `improve-codebase-architecture`, `tdd`, `wait-what` and `pr` keep them; "glossary" stays an ordinary noun.
- `retro` is manual-only with metadata and body guards, and report-only: implementing a candidate, commits, CI or hook changes need separate authorization. It reads the current session directly; a past session the user names is consulted through an OMP `seance` task, never a newest-file guess. Its reviewer agent and `CODING_STANDARDS.md` map to `code-review` and the repo's own standards file. Its pointer to pstack `reflect` went with that skill on 2026-11-16.
- `tdd` (2026-11-16): the description triggers only on a test-first request by name ("TDD", "test-first", "red-green-refactor", a failing test before the code). Upstream's "build features or fix bugs" and "wants integration tests" loaded it in ordinary feature work. The body is unchanged.
- `pr` only drafts the body; pushing, opening or editing a PR is a separate authorized effect. Evidence is what the session observed, never fabricated.
- `resolving-merge-conflicts` stages only the paths it resolved or changed to fix the merge, honours a requested abort, concludes the merge or the whole rebase only when the user asked for it to be finished, and never pushes. Upstream staged everything and never aborted.

Other supporting content retains upstream bytes, apart from the `CONTEXT.md` names and the documented wizard dotenv fix. See [the operative policy](../../../DECISIONS_AI_TOOLING.md#6-skills).
