## Local adaptations

Thirteen of the fourteen are manual-only through metadata plus description/body guards, which still allow named composition under an explicitly invoked recipe. `technical-writing` is the exception since 2026-11-16: the model loads it when the deliverable is a substantial human-facing document. Hermes ignores the metadata gate. OMP/Hermes equivalents replace Cursor-specific loading, delegation, model slugs and transcript paths. Read-only means an actual restricted tool grant, checked per dispatch: an agent type such as `scout` is not a sandbox, because a `task` spawn can inherit MCP and custom tools. Otherwise investigate in the parent or supply frozen input to tool-less reviewers.

| Methods | Changes to preserve |
|---|---|
| `how`, `why` | Manual-only description prefix, body guard and read-only statement on both. `how` answers a narrow question inline and otherwise spawns one read-only explainer: OMP `scout` with a checked grant, Hermes `delegate_task` without write tools. `why` reads only sources the user already connected and writes nothing back. |
| `blast-radius` | Report-only, separately authorized effects. Its multi-model escalation is one `review-loop` panel round, findings only (no fix step, no further rounds), claimed only from returned model identities. |
| `review-loop` | Local, no upstream package. One frozen `code-review` snapshot per round; tool-less reviewers through `scripts/run_reviewers.py`, which copies attachments into the round's output before dispatch and needs one answering model for a single reviewer and two distinct ones for a panel. A missing model or provider is reported, never substituted. Fixes land in the working tree; commit, push and PR text are separate requests. |
| Verification creation/maintenance | Project `.agents/skills/verify-<app>`; existing runners first. Creation proves one feature, maintenance serially exercises every mapped feature and edits only the verifier. Hermes project trust is explicit; product gaps are reported. Local fork since 2026-11-20 (upstream unchanged since `c49b37a2`), following Lauren Tan's talk "All Code Is Slop (Except Mine)": the interview reads the **Stack** from manifests, lockfiles and CI and asks the user what is missing; creation always builds a driver CLI (subcommands with `--help` examples, JSON output, errors that name the next command, `--dry-run` on destructive subcommands), a **Debug** bullet chosen from what the surface exposes, a doctor that checks the port owner and build freshness and refuses an instance another checkout started, ports, profile and data dir derived from the checkout, evidence across entry points, modes, flag variants and end states, steps that wait for an observable end state instead of a fixed sleep, `eval` only to read state after the user path ran, screenshots as the default UI proof with a video when the states in between matter, a **Smoke test** run by the repo's runner by explicit path (launch, doctor, one drive, cleanup) and listed as run, and user vocabulary in the feature index (also in `references/feature-map-example/README.md`). Maintenance adds step 4 **Smoke test** (a missing one is added as creation defines it), reruns the smoke test after each harness fix, and its edit scope covers the CLI and smoke test. |
| `technical-writing`, `unslop` | `technical-writing` auto-loads for document deliverables: no `disable-model-invocation`, the description leads with the trigger, and the body limits it to that document. `unslop` stays named cleanup only and accepts `technical-writing`'s cleanup step as an invocation. Preserve domain terms, literals, quotations, confidence language and file conventions. Agent documents route to `writing-for-agents`; unslop rule IDs stay stable. |
| `show-me-your-work` | Resolve its installed script; reserve a unique directory and sole-writer log for each run, including children. Audit owned files against scoped transcripts, never ownership inferred from shared-log timestamp stretches. Keep six-column TSV and sanitization unchanged. Commit permission is separate; cross-model claims require verified identity. On OMP the trail review runs through `review-loop`'s `scripts/run_reviewers.py` (2026-11-20): prompt on stdin, context files disabled, identity read from `reviewers.json`; its own `omp -p` line passed the trail as one argument and loaded context files. Without `review-loop` installed the review is reported blocked. |
| `recall` | Explicit session/workspace scope, native timestamps and record types—not newest-file or slug guesses. Transcript reconstruction remains distinct from durable-memory retrieval. On OMP (reviewed at 18.18), `recall` discovers sessions through `archive` and consults each through a `seance` task; raw transcript reads are for record-level checks only. The shared-record sweep spawns one investigator per connected source, each holding read and query tools only. |
| `teach` | Invocation authorizes its named `how`/`why`/`unslop` runs, loaded natively; a narrow question stays on `how`'s inline path, and `why` is read while `how`'s explainer runs. Output is the reply only: no edits, lesson files or learning records. `why`'s confidence language is kept. Mermaid where rendered, else ASCII; image generation only when the session exposes a tool, else ASCII sketches. `unslop` is one pass per reply. |
| `benchmark-checklist` | Seven questions intact. Invocation covers local benchmark and profiling runs, not stopping processes the user owns: interleave and say so. Unvendored playbook references become self-contained baseline/harness rules; PR bodies keep one primary number through the native `pr` skill. |
| `correct` | Levels in order, docs last; each check proven on a real past mistake; rule table kept. History mining is read-only. Invocation covers working-tree guard edits; each commit, CI workflow push and exception approval is separately authorized, so it prepares one commit-sized change per class and names what would land. An exception to a ban goes in the check's configuration, scoped to its file, and disable comments for ban rules are blocked; upstream puts every exception on the offending line (2026-11-21). The block is proven: the check still fails on the past mistake with a line-level and a file-level disable comment. In the talk, agents justified quick fixes in comments and the fixes spread; blocking disable comments on a ban is our step from that, not hers. |
| `sharpen` | Upstream method text intact; only the manual-only description prefix and a one-line body guard are added. It answers in the reply and changes nothing. |

Supporting prompts retain their method contracts with those adaptations. Native Hermes model review requires capability/identity verification; the working route uses installed OMP. See [the operative policy](../../../DECISIONS_AI_TOOLING.md#6-skills).

## Updating

Re-copy selected complete packages at a reviewed revision, reapply these adaptations and retain the local `review-loop` package and both licences. Compare against the old upstream revision, update this record and verify installation. New tags alone do not justify discarding the adaptations.
